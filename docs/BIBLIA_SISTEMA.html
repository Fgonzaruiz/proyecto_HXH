🎯 1. Visión y Stack
Objetivo: Foro de rol Hunter x Hunter sobre MyBB con módulo RPG custom (game/) que implementa mecánicas nativas del universo HxH — no adaptaciones de otro sistema.
CapaTecnologíaDecisión
CMS baseMyBBAuth, sesiones, permisos, posts, hilos
BackendPHP 8+Módulo game/ sobre MyBB
Base de datosMySQL vía $dbSin ORMs. Sin backends externos en prod (D001)
CSSVanilla CSSUn único archivo: rpg_custom.css
JSVanilla ES6+Un archivo por feature en jscripts/game/
TemplatesMyBB templatesFuente en front/templates/, XML como artefacto
ContratosOpenAPI 3.0packages/contracts/
Principios de diseño:
D001
MySQL vía $db de MyBB. Sin backends externos en prod.
D002
Ruta de módulo neutral: game/ siempre.
D003
PHP orquesta. Lógica de negocio vive en Application/Services.
D004
Cero style= inline en templates. Cero <script> inline.
D005
Un endpoint AJAX por acción. Un archivo por endpoint.
D006
Cero valores HxH hardcodeados en lógica PHP. Todo desde config/universe.php.

⚡ Fórmula power_score
score = base * type_affinity * (1 + 0.15 * conditions) * (1.30 si voto activo) * (0.50 si voto roto)

base = hatsu_level * 10   (0–100)
type_affinity = 1.0 + ((stat_relevante - 10) / 180)   (1.0–1.5)

🐘 5. Backend PHP — Convenciones

Patrón de endpoint AJAX

define IN_MYBB→ require global.php→ require bootstrap.php→ header JSON→ verificar sesión→ verificar CSRF→ verificar POST→ obtener PJ→ UseCase→execute()→ json_encode resultado 
// game/ajax/hatsu_create.php
define('IN_MYBB', 1);
require_once dirname(__FILE__, 4) . '/global.php';
require_once MYBB_ROOT . 'game/public/bootstrap.php';
header('Content-Type: application/json');
if (!$mybb->user['uid']) die(json_encode(['ok'=>false,'error'=>'No autenticado']));
verify_post_check($mybb->get_input('my_post_key'));
if ($_SERVER['REQUEST_METHOD'] !== 'POST') die(json_encode(['ok'=>false,'error'=>'Solo POST']));
$char = game_get_character_by_uid($mybb->user['uid']);
if (!$char) die(json_encode(['ok'=>false,'error'=>'Sin personaje']));
try {
    $useCase = new CreateHatsuUseCase($db, $char);
    $result  = $useCase->execute($mybb->input);
    echo json_encode(['ok'=>true,'data'=>$result]);
} catch (ValidationException $e) {
    echo json_encode(['ok'=>false,'error'=>$e->getMessage()]);
}

    state: { primaryType:null, conditions:[], vowActive:false },
    init() { this.bindEvents(); this.updatePreview(); },
    calculatePowerScore() {
      const base     = parseInt(document.getElementById('char-hatsu-level').value) * 10;
      const condMult = 1 + (0.15 * this.state.conditions.length);
      const vowMult  = this.state.vowActive ? 1.30 : 1.0;
      return Math.round(base * condMult * vowMult);
    },
    updatePreview() {
      const score = this.calculatePowerScore();
      document.getElementById('hatsu-power-score').textContent = score;
    },
    async submit(e) {
      e.preventDefault();
      const r = await fetch('game/ajax/hatsu_create.php', {
        method:'POST',
        headers:{'Content-Type':'application/json'},
        body: JSON.stringify({ my_post_key: postKey, ...this.state })
      });
      const data = await r.json();
      if (data.ok) this.showSuccess(data.data);
      else this.showError(data.error);
    }
  };
  document.addEventListener('DOMContentLoaded', () => HatsuBuilder.init());
})();

⭐ Hatsu Constructor — MVP ABSOLUTO
Prioridad máxima. Esto es lo que diferencia objetivamente del mercado. Ningún competidor tiene un sistema generativo de Hatsu con fórmula de power_score automatizada.

Flujo completo:

PJ tiene tipo Nen→ hatsu_workshop.php→ Formulario (tipo+condiciones+voto)→ Preview power_score en tiempo real→ hatsu_create.php (approved=0)→ Notif al staff→ hatsu_review.php→ Aprobado → notif al PJ
⚡ Power Score Formula
score = (hatsu_level × 10) × type_affinity × (1 + 0.15 × num_conditions) × vow_mult

vow_mult: 1.30 si voto activo, 0.50 si voto roto
type_affinity: 1.0 + ((stat_relevante − 10) / 180) → rango 1.0 a ~1.5

Condiciones: texto libre validado por staff. Cada condición activa sube el multiplicador. Son restricciones narrativas con consecuencias mecánicas reales.

Votos: si el staff marca rotura de voto → vow_broken=1 → power_score ×0.50 hasta restauración.

🃏 Sistema de Cartas (Cards System) — Feature Completo

El foro implementa un sistema de coleccionables y equipamiento basado en Cartas (Cards). Cada carta representa una habilidad, un objeto, un don o un aliado menor, representado mediante su respectivo tipo en la columna card_type.

Tipos de Cartas y Equivalencias:

Tipo en DB (card_type)Significado temático HxHFuncionamiento Mecánico
tecnicaTécnica de Combate ComúnHabilidades generales que cualquier personaje puede aprender (ej. estilos de artes marciales no Nen, sigilo básico, combate con armas). Otorga multiplicadores de ataque o defensa.
equipoEquipamiento e ÍtemsArmas (ej. espadas, kunais), armaduras o accesorios que ocupan un slot de inventario físico. Modifican directamente las estadísticas básicas (stat_strength, stat_resistance) del PJ.
nen_abilityHabilidad Nen (Hatsu Aprobado)Representación en inventario de un Hatsu aprobado de la tabla game_hatsu. Al equiparla, se activa su modificador power_score y sus condiciones en combate. Requiere que el PJ posea el tipo Nen coincidente.
npc_menorAliados e InvocacionesInvocaciones o contratos con NPCs de apoyo (ej. bestias mágicas domesticadas, informantes o mercenarios). Se pueden invocar en combate para realizar un ataque o proveer utilidad y luego entran en cooldown.

Flujo de Asignación y Compra (Tienda de Cartas):

PJ tiene Jenny suficiente→ POST /ajax/cards_purchase.php→ Verifica stock e inventario libre→ Resta Jenny e inserta en game_inventory→ Notificación de obtención

Slots de Equipamiento Limitados:

Un personaje no puede equipar infinitas cartas. Existen slots restringidos administrados en game_inventory:

  • Slot Armas (Main Hand / Off Hand): Máximo 2 cartas equipadas de tipo equipo que tengan tag de arma.
  • Slot Armadura (Body / Accessory): Máximo 1 armadura + 2 accesorios.
  • Slot de Habilidades (Nen / Técnicas): Espacio para equipar hasta 4 cartas de tipo nen_ability o tecnica simultáneamente en combate. Para equipar un Hatsu (nen_ability), el personaje debe estar en estado Ten o Ren (validado vía nen_state_change.php).

Efectos Dinámicos y serialización JSON:

La columna effects_json en la tabla game_items almacena un objeto JSON con los modificadores exactos que se aplican al portador. Ejemplo de payload:
